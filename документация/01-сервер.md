# Сервер: ставим компаньона рядом с Jellyfin

[English](../docs/01-server.md) · **Русский**

Компаньон — это одна программа на Python. Она живёт на той же машине, где
Jellyfin, перекодирует видео под экран телефона и раздаёт его потоком.

Ставить его в систему не нужно: это папка с файлами и один запускающий файл.

## Что потребуется на машине

**Python 3.8 или новее.** Годится и распакованный (embeddable) — тот, который
не ставится, а просто лежит папкой. Сторонние библиотеки не нужны ни одна.

**ffmpeg и ffprobe.** Оба уже есть внутри Jellyfin — обычно в
`C:\Program Files\Jellyfin\Server\`. Второй ffmpeg ставить не надо.

> **ffprobe обязателен.** Им снимается настоящая частота кадров записи.
> Назначать её рукой нельзя: однажды поставили 25 там, где было 24, и
> кодировщик добавил 155 лишних кадров — по одному в секунду. На телефоне это
> выглядело как запинка раз в секунду, и причину искали полдня.

**Отдельный пользователь в Jellyfin.** Заведите учётку для телефона — не
администратора. Приложение входит под ней, а компаньону достаточно её токена:
единственное право, которое ему нужно, — читать видео.

## Установка

1. Положите папку компаньона куда угодно, например `C:\jellyfin-companion\`.
   В ней должны быть: `rtsp-proba.py`, `rtp_relay.py`, `sdp-shablon-24.txt`,
   `zapusk.cmd`.

2. Создайте рядом `token.txt` с одной строкой:

   ```
   TOKEN=<токен пользователя телефона>
   ```

   Где взять: войдите в Jellyfin под этим пользователем, откройте панель
   управления → Устройства/Ключи API, либо снимите токен из того же запроса,
   которым входит приложение. Токен — это ключ от вашего кино, держите его как
   пароль.

3. Откройте `zapusk.cmd` и поправьте пути под свою машину. Это единственное
   место, где вообще есть настройки: в самой программе адресов нет.

   ```bat
   set PROBA_PRODUKT=1
   set PROBA_JELLYFIN=http://127.0.0.1:8096
   set PROBA_FFMPEG=C:\Program Files\Jellyfin\Server\ffmpeg.exe
   set PROBA_FFPROBE=C:\Program Files\Jellyfin\Server\ffprobe.exe
   set PROBA_TOKEN_FILE=%~dp0token.txt
   set PROBA_ZHURNALY=%~dp0zhurnaly
   set PROBA_PORT=8554
   set PROBA_PORTS_FROM=40000
   set PROBA_PORTS_TO=40063
   set PROBA_EKRAN=320x240
   ```

4. Запустите `zapusk.cmd`. В окне должно появиться:

   ```
   === RTSP-сервер запущен, порт 8554 ===
   ```

Всё. Телефон уже может к нему обращаться.

## Настройки целиком

| Переменная | Что задаёт |
|---|---|
| `PROBA_JELLYFIN` | адрес Jellyfin. На его же машине — `http://127.0.0.1:<порт>`: тогда запросы не выходят в сеть вовсе |
| `PROBA_FFMPEG`, `PROBA_FFPROBE` | полные пути; в `PATH` их нет |
| `PROBA_TOKEN_FILE` | файл с `TOKEN=` |
| `PROBA_ZHURNALY` | папка журналов (создаётся сама) |
| `PROBA_PORT` | порт разговора с телефоном. **Не 554** — см. [главу про сеть](02-сеть.md) |
| `PROBA_PORTS_FROM`, `PROBA_PORTS_TO` | диапазон портов потока. 64 порта = 16 одновременных просмотров |
| `PROBA_EKRAN` | экран телефона по умолчанию: `320x240`, для Nokia E90 — `800x352` |
| `PROBA_VIDEO_PKT` | предел размера пакета видео, по умолчанию 1100 байт. Меньше — если канал идёт через туннель |
| `PROBA_STROGO=1` | требовать токен ото всех, включая домашнюю сеть |
| `PROBA_ZAPOLNIT=1` | заполнять экран с обрезкой вместо чёрных полей |

### Про `PROBA_EKRAN`

Обычно эту настройку трогать не нужно: **приложение само называет свой экран**
при каждом запуске. Один компаньон спокойно обслуживает и обычный телефон, и
E90 — каждому своя картинка, настраивать ничего не надо.

Значение из `zapusk.cmd` нужно только для плеера, который пришёл по голому
адресу, без приложения.

### Про `sdp-shablon-24.txt`

Это не декоративный файл. В описании потока есть строка настройки декодера,
которую выдаёт только сам кодировщик: чтобы её получить, надо перекодировать
кусочек записи, а это десятки секунд, пока телефон ждёт ответа.

Зависит она лишь от размера картинки и частоты кадров, поэтому считается один
раз и кладётся файлом рядом. Готовый на 24 кадра идёт в комплекте — он самый
частый. Для записи с другой частотой компаньон соберёт свой при первом
обращении, один раз.

Именно это и делает всё затею возможной: иначе на каждую серию уходило бы
полминуты ожидания.

## Чтобы работало само: служба Windows

Запуск двойным щелчком годится для пробы. Для постоянной работы оберните
`zapusk.cmd` службой — например через NSSM (это один .exe, ставить в систему
ничего не надо).

Что учесть:

* Службе хватит прав **LocalService**. Доступ к дискам с кино ей не нужен
  вообще — видео она берёт у Jellyfin по сети, как обычный клиент.
* Нужны: чтение своей папки, чтение `token.txt`, запись в папку журналов.
* `token.txt` стоит закрыть правами: читать его должны только служба и вы.
* Поставьте зависимость от службы Jellyfin, чтобы та стартовала первой.

> **Если Jellyfin у вас запускается значком в трее**, он умрёт при выходе
> пользователя из системы — и компаньон останется без источника. Для
> постоянной работы обе части делают службами.

## Проверка, что всё живо

В папке журналов появляется `rtsp.log`. Запустите серию с телефона и
посмотрите в него: там видно каждый шаг — кто пришёл, что попросил, сколько
пакетов ушло, на что жалуется плеер.

Строки, по которым всё понятно без догадок:

```
от плеера пришло: 40000=3, 40001=335, 40002=3, 40003=168
плеер сообщает: потеряно 0.0% за интервал, всего 0, дрожание 12 единиц
```

Первая — что телефон до нас достучался. Вторая — его собственная жалоба на
качество связи: сколько потеряно по дороге. Ноль потерь — канал чистый.
